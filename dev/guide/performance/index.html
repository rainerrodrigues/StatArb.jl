Memory model

  • Panel. A PricePanel holds five n_assets × T Float64 matrices (mid, log mid, spread, volume, depth) plus a BitMatrix of tradable bars, so about 41·n·T bytes. The constructor converts each input in one pass and only builds a default matrix for a field you leave out.
  • Live state. Each spread holds k × 2W doubles for its mirrored ring buffer, two short rings and a 2×2 or 3×3 filter state. All per-check statistics run in shared workspaces.
  • Formation. distance_screen! runs on a reusable ScreenWorkspace: the normalised window (W × n), one Gram block (n × 256) and a heap of top candidates. It never builds the n²/2 list of pairs. Basket candidates reuse the same normalised window.
  • Results. Telemetry is stored as StructVectors of small immutable records, so each column is one contiguous vector.

Formation shortcuts

  • Johansen skip gate. A pair's selection p-value is max(p_EG, p_Johansen), and Benjamini-Hochberg at level q never accepts p > q. Formation therefore skips the Johansen test whenever p_EG > q, which is about two thirds of screened candidates and removes ~70% of each skipped pair's cost. Selections are provably unchanged, and the logged minimum p-value is kept exact by testing skipped pairs lazily only when they could hold it.
  • FormationCache. A formation's selection depends only on the data window and the selection settings, so backtests that differ in filter, signal, risk or execution settings can share it. sensitivity_sweep does this by default, which makes the default 15-run sweep 1.9× faster.
cache = FormationCache(panel)
for q in (0.5, 1.0, 2.0)
    run_backtest(panel, BacktestConfig(kalman = KalmanConfig(q_scale = q)); formation_cache = cache)
end
cache          # FormationCache(16 selections, 32 hits, 16 misses)

Where the time goes

On the 270-asset run, formation takes about 55% of the time (pair tests, basket scans and the screen) and the rolling health checks about 40%. Formation runs threaded by default. The health checks are exact recomputations of Engle-Granger and Johansen on the rolling window, about 2 µs and 10 µs each. They are deliberately not replaced by incremental moment updates, which would trade exactness for speed.

CI runs the benchmark on every push and posts the results in the job summary.

Robustness guards on the hot path

  • A filter whose state, covariance or outputs become non-finite is rebuilt from the spread's own rolling window, and the spread is quarantined. Every rebuild is logged in res.model_resets.
  • Square-root impact is capped at exec.max_impact (50% by default), so no fill can have a non-positive price.
  • BLAS's global thread setting is saved and restored once across nested or concurrent threaded scans.

How the kernels avoid allocating

  • Workspaces: OLSWorkspace, EGWorkspace and JohansenWorkspace own every buffer they need. Create one per thread and reuse it.
  • Small dense algebra: Cholesky factorisation and triangular solves on matrices of dimension ≤ ~20 use hand-written loops, which avoids LAPACK's call overhead and the heap allocations of the high-level wrappers.
  • LAPACK directly: the Johansen eigenproblem calls dsygvd through ccall, with WORK and IWORK buffers owned by the workspace.
  • Static arrays: the Kalman state lives in SVector/SMatrix fields, so updates stay in registers.
  • Contiguous windows: mirrored ring buffers hand out contiguous views, so the rolling statistics read memory in order.

The test suite asserts @allocated == 0 for every kernel, measured inside a function. At the top level of a test block, Julia also counts the boxing of captured variables. CI runs JET over the whole package, so a type instability or a possible MethodError fails the build.

Threading tips

  • Start Julia with -t auto.
  • Formation scans and sweeps pin BLAS to one thread while they run.
  • sensitivity_sweep runs one backtest per task. It turns off threading inside formation, so the two levels of parallelism don't oversubscribe the cores.
